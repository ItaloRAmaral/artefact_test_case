**Goal:** `/tasks/new` and `/tasks/[id]/edit` share one functional form that validates with the shared schema before sending, disables saving while it runs, shows back-end errors, and on success refreshes the caches and returns to the list, which shows a success toast; a missing task shows a message on the edit page.

**Architecture:** the toast moves from `TaskList` into a `ToastProvider` in the root layout, which stays mounted across navigations, so the form can show `Task created.` on the list it navigates to. `src/client/tasks/task-form.tsx` holds the form (`useState`, the shared Zod schemas, the create and update mutations); `src/client/tasks/edit-task.tsx` loads the task in the browser with `task.getById` and renders the form. The pages are thin Server Components; the edit page reads `params` inside `<Suspense>` (Next.js 16 with Cache Components).

## Global constraints

- Contract (roadmap, D-15, D-25): `task.create` `{ title, description? }` → `TaskDto`; `task.update` `{ id, title, description? }` → `TaskDto` (an omitted or blank `description` is stored as `null`); `task.getById` `{ id }` → `TaskDto`, `NOT_FOUND` (`TASK_NOT_FOUND`); create on a full store → `CONFLICT` (`TASK_STORAGE_FULL`). `TaskDto = { id, title, description: string | null, createdAt }`, typed in client code by `import type` only (D-26).
- Validation (D-06, `CLAUDE.md` hard rules): the form validates with the same schemas the procedures use (`createTaskInputSchema`, `updateTaskInputSchema` in `src/shared/tasks/task-schemas.ts`), on submit, and sends the parsed `data`; it never writes a rule again. Field messages are the schema's: `Title is required`, `Title must be at most 120 characters`, `Description must be at most 1000 characters` (limits from `task-limits.ts`).
- Errors (D-07): a failed save shows `getErrorMessage(error)` (Task 1 of sub-plan 4) in the toast's alert region: `This task no longer exists.`, `The task list is full. Delete a task to add a new one.`, `Some fields are invalid.`, or the generic `Something went wrong. Check your connection and try again.`. Server `fieldErrors` are not shown per field: the form already checked the same schema, so a server `BAD_REQUEST` means a bypassed client.
- Toast (D-28, kept): `role="status"` for success, `role="alert"` for errors, both regions always on the page, 4 s, keyed per result. Texts: `Task created.`, `Task saved.` (proposals of this plan).
- Navigation: after a successful save the form awaits the cache refresh, shows the toast and calls `router.push('/')` (`useRouter` from `next/navigation`). The save button stays disabled from the click until the navigation (`isPending || isSuccess`).
- Route state (Next.js 16.4.6 docs, `02-guides/preserving-ui-state.md`; `next.config.ts` has `cacheComponents: true`): leaving a page does not unmount it; Next.js hides it with React `<Activity>` and keeps the state of up to 3 routes. Without a reset, opening `New task` again after a save would show the old values with Save still disabled (`isSuccess`). `TaskForm` is keyed by `useRouter().bfcacheId` (`04-functions/use-router.md`: it changes on a push or replace navigation, including `<Link>` clicks, and stays the same on back/forward), so each visit through a link starts a fresh form, and the browser's back button still restores a draft. The docs' per-pattern resets were rejected: resetting in the success handler re-enables Save before the navigation, and a `useLayoutEffect` cleanup with a ref needs a reset per piece of state (fields, field errors, two mutations).
- Invalidation (roadmap): create invalidates `trpc.task.list.pathFilter()`; update invalidates it and `trpc.task.getById.queryFilter({ id })`. On the form pages the list query has no active observer (it is absent, or on the hidden `/` page), and `invalidateQueries` refetches only active queries by default, so the list invalidation passes `refetchType: 'all'`: the list is refetched before the navigation and `/` shows the change at once. Both invalidations are awaited inside `onSuccess`, so the mutation stays pending until they finish.
- Edit page (Next.js 16.4.6 docs, `03-file-conventions/dynamic-routes.md` "With Cache Components"): without `generateStaticParams`, params are runtime data and must be read inside `<Suspense>`: `params.then(({ id }) => <EditTask id={id} />)`, as the docs' example. `useRouter` throws `invariant expected app router to be mounted` outside the App Router (`next/dist/client/components/navigation.js`), so component tests mock `next/navigation` (a framework boundary, not our code); `next/link` needs no mock: under Vitest it resolves to `next/link.js` → `next/dist/client/link.js`, which guards `if (!router)`; Task 1 confirms it renders without errors or warnings in jsdom.
- `getById` runs with `retry: false`: TanStack Query's default of three retries would keep a missing task on `Loading task…` for about 7 s.
- UI text (English, proposals of this plan): headings `New task`, `Edit task`; labels `Title`, `Description` (a `<textarea>`); button `Save`, `Saving…` while pending; links `New task` (list page), `Edit` per task (`aria-label` `Edit <title>`), `Back to tasks` (form pages); loading `Loading task…`.

## Review focus

- **Blank or whitespace-only title** → field message `Title is required` under the field (`aria-describedby`, `aria-invalid`), no request sent.
- **Title of 121 characters, description of 1001** → the schema's limit message under that field, no request.
- **Double click on Save** → the button is disabled from the click until the navigation, so one task is created.
- **Store full on create** → toast `The task list is full. Delete a task to add a new one.`, the form keeps the values, no navigation.
- **Network failure on save** → generic toast, the form keeps the values, no navigation.
- **Missing task when opening the edit page** → `This task no longer exists.` at once (no retries), no form.
- **Id longer than 36 characters in the URL** → the server rejects the input shape: `Some fields are invalid.`, no form (accepted: no extra code for a hand-typed URL).
- **Task deleted while it is being edited** → on save, toast `This task no longer exists.`, no navigation.
- **Description emptied on edit** → stored as `null`.
- **A background refresh of the task fails while editing** → the form and the typed values stay (`isLoadingError`, as the list in sub-plan 4).
- **Reopening a task right after saving it** → the form shows the saved values, not the cached old ones (the `getById` invalidation).
- **The toast after navigating** → shows on the list (the provider lives in the layout).
- **Opening the form again after a save** (the route is kept by `<Activity>`) → a fresh form with Save enabled: empty for create, the saved values for edit.
