# Plan: a colored board look

| Field   | Value                                                                                                                                                                                                                                    |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Status  | Proposed                                                                                                                                                                                                                                 |
| Date    | 2026-11-20                                                                                                                                                                                                                               |
| Request | "agora precisamos melhorar o design desse projeto. Deixar um pouco mais moderno sabe?"                                                                                                                                                   |
| Context | `docs/SPEC.md` §3 (list, form, feedback states; "não é necessário um design elaborado"); DECISIONS D-14, D-29, D-33, D-34, D-35, D-36; `code-style.md` (Next.js and React, accessibility basics); the `frontend-design` skill's guidance |

**Goal:** the app looks like a colored task board: each card is tinted and edged with its status color, the status is picked from a segmented control in the filters and in the form, actions are icon buttons, and one typeface, Bricolage Grotesque, gives the app a voice.

**Architecture:**

- **Tokens:** colors are Tailwind theme tokens in `globals.css` (`@theme`), redefined once for dark mode, so markup uses one class (`bg-surface`) instead of a light and a `dark:` pair.
- **Status colors:** a status maps to its colors in one CSS rule per status (`[data-status='doing']`); the card, the pill and the picker only set `data-status`.
- **New shared pieces:** a `StatusPicker` radio group and a few inline SVG icons, both in `src/client/shared/`. No new dependency.
- **Server side:** nothing changes in the server, the contract or SSR.

## Global constraints

- **No component or icon library** (D-33). Icons are inline SVG.
- **Font:** `Bricolage_Grotesque` from `next/font/google`, `subsets: ['latin']`, `axes: ['opsz']`, variable weight, set on `<html>` through a CSS variable. Next downloads it at build time and serves it from the app (no request to Google from the browser), so `pnpm build` needs internet (user decision).
- **Accessible names stay as they are:** `Search by title`, `Created from`, `Created to`, `Clear filters`, `New task`, `Edit <title>`, `Delete <title>`, `Status of <title>`, `Close`. Tests find controls by these names.
- **Status labels** stay `To do`, `Doing`, `Done` and `All`, from `TASK_STATUS_LABELS` (D-36).
- **Dark mode** still follows the system (`prefers-color-scheme`).
- **Quality floor:** visible keyboard focus on every control, AA contrast for text, phone width 390 px with no horizontal scroll.

**Type:** Bricolage Grotesque throughout. The optical-size axis makes headings expressive and small text calm, so one family is enough. `Tasks` heading 2.25rem semibold, tight tracking; modal title 1.5rem; task title 1.0625rem semibold; body 0.875rem; labels and dates 0.75rem medium.

**Shape:** cards `rounded-xl` with a 4 px left band; controls `rounded-lg`; pills and segments `rounded-full`. No shadow on cards; the modal and the toast keep one.

**Layout:**

```
Tasks                                   [+ New task]
[🔍 Search tasks…                                  ]
( All | ● To do | ● Doing | ● Done )   From [    ] To [    ]  Clear filters
───────────────────────────────────────────────────── (sticky block ends)
▌ Write the README                         ● Doing ▾
▌ How to run, the stack and the main decisions.
▌ 📅 Nov 20, 2026, 3:38 PM                    ✎   🗑
```

On a phone: search; the segmented control at full width; the two dates side by side; Clear on its own line.

**Principle:** the status is the one bold thing; everything else stays quiet (neutral canvas, one blue accent for actions).

## Review focus

- **Arrow keys in a radio group** change the selection at once. In the filter that applies the filter, like typing a search. In the form it only changes local state. Both are expected. No test needed beyond the change tests.
- **Radio click target:** the radio covers its segment, invisible, like the pill's select (D-36), so a click anywhere on the segment selects it, and Playwright's `check()` hits the input itself.
- **A done task's title** is muted, not struck through, so it stays readable. Contrast `ink-muted` on `done-tint` is 5.39:1 light and 6.26:1 dark (computed with the WCAG formula). Every text pair in the tokens table measures between 5.16:1 and 10.74:1, so all pass AA.
- **Server HTML:** nothing here depends on the browser, so SSR output and hydration are unchanged (D-14, D-27).

## Security

| Threat                    | How this plan handles it                                                                          | Task and test                       |
| ------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------- |
| XSS in rendered task text | Unchanged: titles and descriptions stay React text nodes; `data-status` takes only a `TaskStatus` | Task 3; existing list tests         |
| Third-party requests      | The font is self-hosted by `next/font`; the browser requests nothing from Google                  | Task 1; checked in the build output |
| Others                    | No input, contract, error or server change: schemas, limits and error mapping do not apply        | —                                   |

## Test plan

| Requirement or review-focus line                      | Level          | Test name                                                                                                                                                                                       | Task |
| ----------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| The picker shows every status, checked by value       | component      | `StatusPicker` › `offers every status`, `checks the given status`                                                                                                                               | 2    |

| The filter applies and clears the status (rewritten)  | component      | `TaskFilters` › `applies a status`, `removes the status when All is chosen`, `shows the status of the filter`, `offers every status and All`, `keeps the other filters when the status changes` | 2    |
| The form saves the chosen status (rewritten)          | component      | the `TaskForm` and `EditTask` status tests, with the radio                                                                                                                                      | 2    |
| Filtering and creating with a status, in the browser  | e2e            | the `list-page` status filter test and the `task-form` status test, with the radio                                                                                                              | 2    |
| Accessible names unchanged after the restyle          | component, e2e | every existing test, unchanged                                                                                                                                                                  | 1, 3 |

- **Levels used and why:** component tests for the new picker and the rewritten status controls; e2e for the two browser flows that used the select. The restyle has no behavior to assert, so it is checked by screenshots (light, dark, phone, modal) with a throwaway Playwright probe, removed afterwards.
- **Test data:** the existing factories and seeds; the picker tests render it with fixed props.
- **Targets:** server coverage is untouched (no server change).
- **How to run:** `pnpm test`, `pnpm test:e2e` one file at a time (the user's RAM constraint), `pnpm lint`, `pnpm typecheck`, `pnpm format:check`.

## Style deviations

None. `StatusPicker` has two callers (filter and form) with the same markup and the same status colors. That is business knowledge in one place, not an early abstraction. The icons are one-line components used by several components.
