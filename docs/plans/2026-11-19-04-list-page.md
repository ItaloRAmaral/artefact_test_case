**Goal:** `/` shows the task list rendered on the server for every request and hydrated without a refetch, with title, description and date, an empty state, a load error, and delete in place with disabled buttons while pending and a toast with the result.

**Architecture:** the React side of tRPC follows the tRPC 11 server-components setup (trpc.io, read 2026-11-19): `src/shared/trpc/query-client.ts` (`makeQueryClient`, used by server and client), `src/client/trpc/provider.tsx` (`'use client'`: `TRPCProvider`, `useTRPC`, `httpLink`, D-25) and `src/server/adapters/trpc/server.ts` (`server-only`: per-request query client and the options proxy). The page prefetches the first page inside `<Suspense>` after `io()` and hands it over with `HydrationBoundary`. The UI lives in `src/client/tasks/` (user decision): `task-list.tsx`, `task-date.tsx`, `toast.tsx` and `error-message.ts`. Components are tested in jsdom against the real router through tRPC's `localLink` and a fresh repository; no mocks of own code.

## Global constraints

- Versions (D-19, newest at least 7 days old on 2026-11-19, checked with `pnpm view <pkg> time`), pinned exactly: `@trpc/client` and `@trpc/tanstack-react-query` 11.28.0, `@tanstack/react-query` 5.107.1; dev: `@testing-library/react` 16.3.3, `@testing-library/dom` 10.4.2, `@testing-library/user-event` 14.6.9 (14.6.13 too fresh), `@testing-library/jest-dom` 7.0.1 (8.0.0 too fresh), `jsdom` 31.0.0 (31.0.1 too fresh). `@vitejs/plugin-react` 6.3.0 only if Vite 8 does not transform the test TSX on its own (Task 1 checks it first).
- tRPC client facts (`@trpc/client` 11.28.0 source, read 2026-11-19): it exports `localLink({ router, createContext })`, which builds errors with `getTRPCErrorShape` from the router config, so the error formatter of sub-plan 3 (`data.domainCode`) applies in component tests as it does over HTTP.
- Contract (D-15, D-25): `task.list` input `{ cursor?, limit?, direction? }`, output `{ items: TaskDto[]; nextCursor }`; `task.delete` `{ id }` → `{ id }`; errors carry `data.code`, `data.domainCode`, `data.fieldErrors`; batching is off, so the client uses `httpLink`.
- The list query is an infinite query from the start (roadmap "Pages"): `trpc.task.list.infiniteQueryOptions(TASK_LIST_INPUT, { getNextPageParam: getNextTaskListCursor })`, with `TASK_LIST_INPUT = {}` and the cursor getter written once (`src/client/tasks/task-list-query.ts`), used by the page's prefetch and by `TaskList`, so both build the same cache key. Only the first page shows here; loading more is sub-plan 6.
- Rendering (Next.js 16.4.6 docs in `node_modules/next/dist/docs/`, `cacheComponents: true`): a read the framework cannot see (our in-memory store) completes during prerendering, so the list section calls `await io()` from `next/cache` first ("suspends during prerendering"; with Cache Components, `io()` is preferred over `connection()`, `03-api-reference/04-functions/io.md` and `connection.md`), and it sits inside `<Suspense>` (uncached work outside one blocks the route, `01-getting-started/08-caching.md`). The heading and the fallback are the static shell; the list renders per request.
- No refetch on first paint: `makeQueryClient` sets only `staleTime: 30_000` (the tRPC docs' value; "SSR usually needs a staleTime above 0"), so hydrated data counts as fresh. The prefetch is awaited, so the docs' options for streaming pending queries (`shouldDehydrateQuery` with pending, `shouldRedactErrors: false`) are not needed and are left out.
- Dates (D-14): the server HTML and the first client render show `createdAt` built from the ISO string without locale data, `YYYY-MM-DD HH:mm UTC` (for `2026-11-19T12:00:00.000Z`: `2026-11-19 12:00 UTC`), inside `<time dateTime={iso}>`, so Node and the browser always produce the same text; `Intl` in Node writes a U+202F narrow space before `AM`/`PM`, which a browser may not. After hydration, the browser's locale and time zone: `Intl.DateTimeFormat(undefined, { dateStyle: 'medium', timeStyle: 'short' })`. The switch uses `useSyncExternalStore` (server snapshot `false`, client `true`), so hydration matches and no effect sets state.
- Delete (user decisions): no confirmation; every delete button is disabled from the click until the list has refetched (`onSettled` returns the invalidation promise, which keeps the mutation pending); each button is named after its task (`aria-label` `Delete <title>`, visible text `Delete`); a toast shows `Task deleted.` (`role="status"`) or the mapped error (`role="alert"`), renders next to every list state (also when the last task is deleted and the empty state appears), and disappears after 4 seconds (`TOAST_DURATION_MS = 4000`, a proposal of this plan, confirmed with it); each result gets a new id and the toast is keyed by it, so a new delete restarts the timer.
- UI text (English, proposals confirmed with the plan): heading `Tasks`; fallback and loading `Loading tasks…`; empty state `No tasks yet.`; button `Delete`; dates as above; error messages in Task 1.
- `CLAUDE.md` hard rules: no client file imports a value from `src/server/` (`import type` only, D-26), enforced by ESLint on `src/client/**`; `server-only` on `server.ts`; texts by code, never by message (D-07); React renders task text as text, never `dangerouslySetInnerHTML`.

## Review focus

- **Empty list** → `No tasks yet.`, no list element.
- **Task without description** → no description element.
- **Task text with HTML** (`<script>alert(1)</script>`) → shown as literal text; no `script` element created.
- **The list fails to load** (network down) → a `role="alert"` with the generic message, not a blank page.
- **Delete pending** → every delete button disabled until the list has refetched, so the deleted row cannot be clicked again.
- **Deleting the last task** → the success toast stays while the empty state appears.
- **Delete of a task already gone** (deleted elsewhere) → toast `This task no longer exists.`, and the list refetches, so the stale row disappears.
- **Delete with the network down** → toast with the generic message; the row stays.
- **Toast** → disappears after 4 s; a second delete within those 4 s restarts the timer, even with the same text.
- **Unknown error code or missing `data`** → generic message (roadmap).
- **First load** → the task is in the server HTML, no `task.list` request fires, no hydration error in the console (roadmap, D-14, D-18).
- **Time zone** → the server HTML shows UTC; after mount the browser's zone (tested with `TZ=America/Sao_Paulo`, UTC−3 with no daylight saving).
